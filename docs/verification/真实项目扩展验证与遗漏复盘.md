## 两项失败的复核

### D009-T01：历史迁移测试的预期停留在第四次迁移

位置：`tests/oauth-migration.test.ts`。测试从 001 执行当前迁移，再要求数据库结构只出现 002–004 的变更，并要求迁移清单只有四项。实际项目已经包含 005 考试时长、006 注册保护、007 统一身份迁移；断言报告出现这些新列与表。

归类：**测试维护缺口**。既有预期与已存在的迁移明显不同，不据此声称数据库迁移损坏；但不能直接删除新字段差异或更新预期来判通过。后续应从已批准的升级合同逐项核对数据保留、约束变化、重复执行和回滚兼容，再更新独立迁移用例。

### D009-T02：历史注册回归未提供新增的注册验证凭据

位置：`tests/review-regressions.test.ts:56`。脚本直接请求注册验证码，实际得到 HTTP 400 / `REGISTRATION_PROOF_REQUIRED`，后续“错误次数持久化”断言没有运行。

归类：**测试维护缺口，后续断言未验证**。当前注册保护要求先取得有效 proof，服务端已有保护测试通过；这不等于该历史脚本剩余断言已经被替代验证。应使用合法的测试验证凭据完成准备，保留原错误次数与重启持久化断言。

被验收项目与上述两个测试均未修改。

## 环境失败保留与归因

首轮服务端 5 处失败、一项跳过；构建也失败，均保存在 `attempt-1/`。随后复核发现：

1. embedding 测试会启动真实 runtime，必须先有 `server/dist` 和前端构建产物；初始镜像缺少这些产物。
2. 初始临时存储只有 1 GiB，而应用另外要求预留 1 GiB，正常返回 507。调为 4 GiB 临时存储后，原业务代码不变，上传测试通过。
3. 构建复制到受限临时挂载后执行 tsc 得到 Permission denied；改为镜像构建阶段运行原 `npm run build` 成功。未进一步证明该权限错误的唯一底层原因。
4. 首轮未开启 1 GiB 实测开关；重跑显式设置 `TEST_BIG_MATERIAL_UPLOAD=1`，该项真实执行通过。

先前失败没有被删除，环境修复和测试重跑也没有被描述为修复了业务缺陷。
