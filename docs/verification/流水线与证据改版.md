## 数据与事实边界

- 新执行保存 pipeline 阶段记录：id、status、started_at、finished_at、duration_ms、detail；阶段开始及结束持久化，100 ms 更新显示计时、1 s 刷新执行快照。
- duration_ms 由单调时钟测量。服务中断恢复时，无法测得的阶段耗时显示“未记录”，不把重启前后的墙钟间隔当作执行耗时。
- 旧记录只使用已有 layer_runs 时间；缺失的阶段耗时保持“未记录”，不改写历史记录。
- inspections 是从校验通过的原始产物派生的只读视图；case_plans 是绑定固定套件摘要的复现说明。它们不是新的执行器或裁决规则。
- 直接观察来自 Bandit JSON、Playwright 断言信封和 axe JSON。复现说明来自冻结用例，不把后续未执行断言描述为已验证事实。
- Shell 条目明确为静态命中，未运行注入载荷，也未证明外部入口可达。越权条目能证明状态码 403/200 不符；正文断言没有执行时不声称已证明具体内容泄露。
- 相同幂等键的“两个订单 ID 不同”只在最终 ID 比较断言失败时归纳；若前面的 HTTP 状态断言失败，只显示实际失败，不推断后面的业务结果。
- 不完整或未知格式不能解读成零缺陷；证据读取失败时移除未核实的观察值和现场片段。

## 自审发现与修正

1. 空 Bandit 日志误显示为复现轨迹：区分空文本和 ZIP，解释日志为空，检测结论查看报告。
2. 时间格式只显示毫秒：显式指定时、分、秒，并增加格式验证。
3. 运行中给本层全部检查标“执行中”：改为“待报告”，不推测单条用例的即时状态。
4. 通过项观察值使用失败色：颜色跟随实际结果。
5. 提前失败仍归纳后续结果：发生经过绑定真实断言位置；缺少 axe violations 不是零违规。
6. 重启后耗时可能包含停机时间：没有单调时钟测量值时保持未知；旧分层时间仍如实呈现。
7. 流程中的具体缺陷打开错误条目：按所点发现 ID 打开详情。
8. 窄屏选中阶段/文件可能被裁掉：在容器内保持选中项可见，不移动整页；修复窄屏关系区间距。
9. OPA 阶段结束时有机会先发布 completed 而没有最终结束时间：终态只在结束时间与完整性一起写入；真实组件测试拦截每次保存验证这一点。
10. 隔离包回放发现相对数据目录会产生不一致的执行器输出路径：Store 入口统一解析为绝对路径，补充回归检查；默认目录和相对目录的隔离实跑均已核验。
