## Review 发现与修正

1. 失败执行无法直接打开最终门禁产物：添加判定依据及证据范围，保持单个证据阅读器。
2. 历史列表显示未校验的旧 allow：改用派生 snapshot；修改产物后的详情、历史、报告均为 inconclusive，旧记录不被重写。
3. Bandit 有发现且含 errors 时被归为确认缺陷：优先识别工具不完整，不把工具错误说成业务漏洞。
4. 原始 JSON 被重新序列化：改为登记执行器输出的原始字节，真实组件测试核对三份报告与源文件逐字节一致。
5. 原地重复执行、历史同项重复选择：前者拒绝且不改变旧记录，后者保留当前视图。
6. axe/gate 原始报告被套用断言摘要：仅识别有效的断言信封，其余 JSON 保持原文。
7. 通过项沿用缺陷名称、证据定位不清：主要文字改为冻结预期；通过项可直接打开证据，关系栏与文件选择保持一致。

首轮自审与 39 项测试后进入用户模拟；模拟发现的 UI 问题继续修正、自审、类型检查和构建，再复查对应路径，未把第一次自审当作绝对无缺陷证明。
