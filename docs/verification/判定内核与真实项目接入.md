D008 · 产品/API 0.6.0 · 2026-10-17。承接 D007 的 M0 与 M1，先修复错误放行风险，再把现有测试接入真实项目。本批是已实现范围的验证记录，不是“已全面超过竞品”的结论。

## 本批结论

- Bandit、Playwright/axe、Node JUnit 的原始报告经过统一校验，OPA、API、页面与导出共用校验结果。空报告、目标或实际测试不符、跳过/重试、执行错误均不能作为通过依据。
- 标准、测试与策略按执行保存，历史结论与“是否适用于当前文件”分开。单条损坏记录不会再破坏整个目录；目录一次获取，单次读取共用证据缓存。
- 新增显式项目配置、文件快照、离线容器与 Node 原生测试适配器。Web 只能选择已登记项目，不能提交任意宿主命令或挂载。
- 真实目标选用本机 `110lab-assessment`：既有两组业务规则回归，20 个测试通过。副本中的受控倒计时回归被拒绝，失败原文可追溯。
- **M1 仍未完成 Web/API 端到端闭环。** 当前只支持无额外依赖的 Node 原生测试所需文件；没有对整个考核系统做正式交付验收。

## 2. 判定链与证据

`已登记标准 → 冻结文件 → 受限执行器 → 原始报告 → 报告校验 → OPA → 页面/导出`。

原始报告校验检查：格式、工具错误、实际用例/文件、是否跳过/重试、执行退出码、原始与派生结果一致性、附件引用。XML 使用 defusedxml 禁止 DTD/实体解析，按 Node 实际输出支持根级 testcase。报告内容摘要匹配只是必要条件，不能取代这些语义校验。

校验不通过的记录显示“无法下结论”，保留 `recorded_decision` 以便审计；无效结果不能继续显示成已验证缺陷或通过项。历史 JSON 不重写。`applicability` 单独提示当前文件/标准已变化，旧通过不得用于新目标放行。

示例标准升级为 local-v2；local-v1 标准及策略保存在版本登记表。新执行保存标准/策略/测试/目标输入快照。真实项目按内容摘要归档契约，冻结测试文件及预期测试名称；更改测试/来源文档须登记新配置版本，不能沿用旧标准偷偷删断言。

## 3. 执行边界

复用 Node.js Test Runner、JUnit、JSON Schema、defusedxml、Docker、OPA；已有 Bandit、Playwright、axe 继续使用。没有自研测试引擎，也没有调用模型接口。

项目容器固定 Node 镜像摘要，网络为 none，根文件系统与源代码挂载只读，非 root，移除 capabilities、禁止提权；限制内存 256 MiB、CPU 1、PID 64、单组执行 45 秒，stdout/stderr 各 4 MiB。超时/超量/清理失败均不能放行。只挂载执行快照；不传宿主凭据，不挂载 Docker socket。用完删除本次容器。

实测镜像：`node@sha256:ebfe2f90462722a7a4de65e91990e97fe0d401c70e0e762c5b53302f905ec1c1`，本机 arm64。当前实现要求镜像已在本机；本批未验证其他架构或全新机器安装。Docker 是进程隔离边界，不是对恶意代码的绝对安全证明；生产多租户执行仍需专用隔离节点及进一步加固。

限制：旧演示夹具仍由固定宿主执行器运行；此次离线容器适用于新接入的项目，不宣称全部执行路径已经统一沙箱化。标准/报告/摘要仍由本机控制面管理，未接入独立签名或外部信任根。

### 受控反例的具体经过

仅在本项目 `artifacts/d008/regression-control/target` 下建立所选文件副本，把 `formatRemain` 的小时计算从 `Math.floor(total / 3600)` 改为取模 24。需求文档与两个测试文件保持原摘要。已有测试要求 24 小时显示 `24:00:00`，实际得到 `00:00:00`，Node 返回失败、JUnit 保留断言与 `duration.test.mjs:29` 位置，OPA 返回 reject。

这是一处人为注入的验证反例，不是发现原项目目前存在该缺陷；一个反例不能推导检出率或泛化优势。首次适配把 JUnit 根级 testcase 误判为缺少 suite，已按真实 Node 输出修正并重跑全部回归；失败的调试记录未冒充有效通过。

## 5. 使用与复验

1. 在终端审阅并登记配置：`.venv/bin/python scripts/project.py register projects/assessment-core.json`。
2. 页面“新建验收”选择“110lab 考核系统 · 业务规则回归”，显示目录、版本、标准数和测试数；“开始验证”产生新执行 ID。
3. CLI 可用 `.venv/bin/python scripts/project.py run assessment-core`；退出码 allow=0、reject=1、inconclusive=2。
4. `/api/projects` 列出已登记对象；`POST /api/runs` 接收 `{"project_id":"assessment-core"}` 或示例 `{"mode":"fixed"}`，只能二选一；额外命令字段拒绝。
5. 流水线按真实阶段展示，项目未覆盖的 L2/L3 标为未执行。点击回归项查看测试清单、失败原文、原始 JUnit；导出报告包含版本与适用性。
6. 配置的 repository 是本机绝对路径，迁移时必须更新并重新核验。测试或标准变化使用新 ID/版本登记；当前没有覆盖旧配置的网页编辑功能。
