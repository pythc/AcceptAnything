# D038 · 大规模结果与复杂仓库通用修复

执行依据：用户要求按诊断顺序修复、无项目专用配方、不改目标、移除平台数据规模上限，并复跑原仓库及其他复杂仓库。

## 设计与实现

- 独立哈希 JSON payload 分离归一报告、模型方案与复核数据，run.json 仅保存分片引用。编码写入逐块落盘；原始证据流式复制和哈希，下载及 Markdown 报告流式返回。
- 默认运行详情只返回一页发现与摘要，分类、查询、前后翻页在服务端执行。总数来自完整数据集，所有页可达；没有按总条数截断。目录摘要按记录和证据状态缓存，避免重复遍历构造全部发现详情。
- 取消固定仓库文件数、快照总容量、单文件、报告/证据32MiB、远程仓库256MiB、任务总数、12个模型批次与10个组件的拒绝或截断。模型单次上下文仍分批，不等于平台总量上限。文件路径、同源、摘要、格式及取消/超时保护继续有效。
- 普通测试 assert 由静态测试发现和 AST 核对，不绑定 Hatch 打包配置。执行异常和跳过项不进入缺陷候选；未知风险继续待复核，不自动确认漏洞。
- 通用编译镜像提供 C/C++、Rust/Cargo、Python 和系统构建依赖，固定真实镜像摘要与版本。Node 镜像复用 tsx 处理 TypeScript 的 .js 源码重导出；优先使用 package.json 声明的构建入口。没有 test 脚本的 Node 组件不安排 npm test。
- Python 根据声明的测试 extra / dependency group 安装测试依赖；根据静态本地导入发现仓库内组件依赖并安排顺序。Rust workspace 自动识别并通过 Cargo 构建、测试，单个命令结果不冒充内部用例数。
- 构建内存不足、导入与执行器异常保持 error，不作为业务缺陷。移除固定1.5GiB组件内存限制，使用当前执行宿主可用资源；真实资源不足仍明确留证。
- 任务或收尾异常时将运行中的阶段同步结束，历史原始记录不重写。

## 验证安排

先跑平台回归与无32MiB证据门槛、5000文件门槛、分页全量可达、分片篡改拒绝、无测试脚本误执行、混合语言发现和本地依赖识别；真实 Docker 验证 TypeScript .js→.ts 加载。

原验收对象按 fbf7bc3278c11975299b9bd0a2ecf200dfd25a05 提交复跑；新增 Flask 与 Fastify 使用新冻结提交验证。不给任何对象提供专用启动或验收配方，不改目标项目、原生测试或模型预期。实际结果、失败、未覆盖与证据在执行后追加。

## 已核对的规模与回归证据

- 平台后端冻结版本全套516项、前端34项通过；另加了执行异常/跳过不进入缺陷候选的断言回归。
- 34MiB JSON原件可流式归档且篡改会被拒绝；5003文件且含9MiB单文件的仓库可识别；231项分页结果全量可达，无重复或丢失。
- Docker内实测 TypeScript相对 .js 重导出可加载对应 .ts，输入3实际输出6；预期独立冻结为6。

- 31,109,487字节原始报告通过HTTP Range返回字节262144–524287，共262144字节；证据原件未截断。
