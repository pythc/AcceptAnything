# D038 补充组件与适用边界

- 本地Python开发态安装使用pip的PEP660 editable流程，由项目原有构建后端（如Maturin、setuptools、Hatch）构建；没有为目标项目重写编译器或测试。
- 测试发现、导入缓存预热、继续执行正常模块均复用pytest的collect-only与continue-on-collection-errors；收集错误保留，正式验证断开安装网络。
- JSON返回字段定位使用[jsonpointer 3.1.1](https://pypi.org/project/jsonpointer/3.1.1/)，复用RFC6901实现；BSD许可随所安装发行包保留。目标返回值用Python标准库dataclasses、Enum和Pydantic自带JSON序列化，不根据预期更改实际值。
- Python工具脚本使用安全脚本搜索路径，HTTP探针改为http_driver.py，避免遮蔽标准库http；响应原件不在1MiB处静默截断。
- 模型只接收独立文档、可调用接口及明确执行契约，完整测试文件、依赖配置、源文件清单仍在冻结方案与原件中归档。缺少对象构造、业务播种、长驻服务等前置步骤时保留unresolved，不把后续输出片段当作无条件保证。
- 导出采用标准库ZIP64、流式文件哈希与逐成员校验，默认只导出选定执行的冻结记录和证据及显式资源，不遍历加入其他项目或凭据。导出目的地不得覆盖原件。

原生测试通过、扫描器有命中、业务用例可执行与整体验收放行是不同事实；工具异常和未测范围不能充当产品缺陷或通过依据。

正式离线阶段复用[Hugging Face官方离线模式](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables#hfhuboffline)：HF_HUB_OFFLINE=1，仅使用现有缓存，API直接抛出OfflineModeIsEnabled；兼容TRANSFORMERS_OFFLINE旧开关。安装及collect-only预热不设置离线开关。没有声明和冻结的模型权重不猜测下载，也不把缺缓存改成通过。

依赖下载和构建临时文件复用标准TMPDIR环境变量及Python tempfile、pip/Cargo现有实现，默认/work/tmp磁盘卷，避免大包占用/tmp的内存盘。Cargo复用CARGO_BUILD_JOBS控制编译并发，不改编译优化或被测源码；操作员可配置正整数并发，策略参与执行版本摘要。资源信息直接读取本容器cgroup文件和df/printenv，不扫描其他容器、项目或凭据。

分词资源准备复用[tiktoken注册表接口](https://github.com/openai/tiktoken/blob/main/tiktoken/registry.py)与[官方缓存/哈希校验](https://github.com/openai/tiktoken/blob/main/tiktoken/load.py)，仅在目标环境已安装tiktoken时工作。代码不写死项目名字或编码列表；读取该发行版注册编码，逐个调用get_encoding，保存发行版本、缓存摘要、成功及失败，不把下载失败算成源码缺陷。真实校准为tiktoken 0.14.0；目标仓库版本按其实际声明解析，并在环境原件中归档。注册资源逐项准备有超时与取消保护，没有编码数量、缓存总字节或仓库大小上限。
