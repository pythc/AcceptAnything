# D033 · 文档选择与模型输入预算修复

2026-10-19。修复用户在 Headroom 选择23份文档后看到原始 FastAPI 422 JSON 的问题。

## 原因和改动

前端复选框不限制选择数量，也没有显示总字符预算；接口则限制4份，设计服务还限制总输入24,000字符。原始错误响应直接作为页面文案。切换仓库时还会残留之前选中的文档和补充需求。

新增 acceptance/planning/basis.py 作为服务端统一限制来源，API与设计服务共用，识别结果向前端返回 limits 和每份文档实际字符数/截取字符数。保持每次最多4份、每份前12,000字符、含补充需求合计24,000字符，补充需求本身最多12,000字符。没有为绕过报错扩大模型输入或静默省略文档。

前端显示“已选份数/上限、字符数/预算”，超过数量或加入后超预算的未选文档不能继续勾选，已选文档仍可取消；补充需求造成超限时禁用模型按钮并说明原因。按目录排序优先展示根README和docs，提供“按目录选择”和清空；该选择是目录启发式，不代表语义审定，也不声称覆盖未选文档。23份候选仍全部保留在滚动列表。

请求失败解析为中文文案，兼容旧接口的422结构，不回显完整 input。切换来源、路径、地址、分支/提交或配置时清空旧依据、补充需求与确认状态。14份技术栈清单折叠展示，原信息保留。

## 验证

- 57项后端定向回归通过（自动方案和远程接入），其中新增3项验证23候选/主文档优先、23文档API拦截、总预算超限在调用模型前拦截。
- 33项前端测试通过，新增7项验证数量、总预算、Unicode计数、跨仓库旧选择、目录选择、错误翻译和空/重复依据。
- TypeScript与生产构建通过。保留既有TestClient依赖弃用警告。
- 实际HTTP提交23份文档仍由服务端返回422，新增模型请求0；这层保护保留，页面提前约束防止再走到该错误。
- 实际浏览器恢复 Headroom 的 https://github.com/headroomlabs-ai/headroom 地址与main分支，重新拉取仍为 fbf7bc3278c11975299b9bd0a2ecf200dfd25a05，识别2625个文件、23份文档。按目录选择得到4份/20,730字符，额外19份不能勾选；加入4,000字符补充需求后24,730超预算，生成按钮禁用并显示中文提示，清空补充需求后恢复；取消一份后其他符合预算的文档可选。
- 页面留下已恢复的Headroom选择入口；没有再次调用模型，也没有把该项目宣称为验收完成。

## 边界

本批修复单次请求的选择和提示，不实现23份文档的多批模型编排或合并覆盖率。未选文档不计入本次覆盖。原验收记录、模型预期和目标源码均未修改。
