## 用户入口与 PRD 增量

1. 新建验收保留本地路径、GitHub/GitLab 地址与分支/完整 SHA。
2. 检测项目清单和公开入口，列出 README/PRD/契约候选；不运行仓库脚本来识别项目。
3. 用户选择独立文档或粘贴需求，可明确本次范围。单文档读取前 12,000 字符、合计最多 24,000；截取位置与整文件摘要保留。超出范围请拆分需求，不声称读完全文。
4. 模型输出中文名称、理由、输入和预期，并逐字引用依据。界面支持逐条预览，确认范围与预期后才执行。
5. 缺依据不调用模型；模型提出 missing_basis、引用不实、截断、模型强度不符或未知环境时，不产生可执行成功记录。
6. 流程、用例详情、原始响应、原文依据、命令、JUnit、逐用例实际 stdout/stderr、门禁与清理证据进入现有三个页面。流水线单行滚动，运行耗时由实时钟计算。

## 技术设计与开源复用

`acceptance/automatic.py` 提供清单驱动的 intake → design → confirmed plan → execute → verification → OPA。不存在按仓库名分派的分支。

- 识别：Go、Node/TypeScript、Python、Rust、Maven/Gradle、.NET、PHP、Ruby、C/C++ 等清单；Go 自动寻找非测试 main 包，并遵守 Go 对 `.`/`_` 目录的排除语义。多入口、多模块或无可靠入口不猜测。
- 可执行适配器：Go CLI；Node/Python 公开模块复用已有独立方案编译器。发现清单不等于该语言或框架已完成运行认证。Web 服务仍需启动/部署契约、测试数据和独立业务要求；不自动套用 GMAH 配方。
- 模型：复用既有有界请求、请求 ID、终态核对和 High 型号验证。CLI 紧凑表只承载输入、预期、短原文引用；可信投影只添加编号和结构，不修改预期。源文件仅用于清单和入口定位，不向模型提供实现函数体作为正确答案。
- Go：固定镜像 `acceptance-go:auto-v1` 的不可变 image ID；Go 1.26 工具链与 [gotestsum v1.13.0](https://github.com/gotestyourself/gotestsum/releases/tag/v1.13.0)，复用 `go mod download`、`go build`、`go vet`、`go test -json`，gotestsum 输出 JUnit 与原始 JSONL。工具链详见 toolchain.lock.json。
- 独立 CLI 驱动：受控 Python 标准库驱动直接执行固定编译产物加 argv 数组，stdin 为数据，不生成任意 shell。JSON 流使用 Decimal 比较保留大整数精度，布尔与数值不混淆；text 精确比较，不剥除有意义空白。每条记录耗时、实际输出、退出状态、预期与依据。超时/执行器异常进入 JUnit error，完整性不成立。
- 安全隔离：源码只读；CGO_ENABLED=0、GOTOOLCHAIN=local、GOFLAGS=-mod=readonly；依赖下载单独阶段有网络，构建/静态检查/原生测试/业务用例无网络；无宿主凭据、无 Docker socket，CPU/内存/PID/超时有界。编译产物单独固定摘要并只读挂载给业务驱动。
- 通用扫描：自动复用 Gitleaks、Syft、Trivy FS、Hadolint、Trivy config，其他栈按既有扫描器目录选择。本批 Go 专用检查为 go vet；未宣称提供完整 Go 污点分析。
- 完整性：源码、文档、工具链、实现版本漂移阻断新执行；模型设计完成后重新核对源码，冻结时再核对。归档保留原始模型响应及草稿，重新投影验证方案，核对文档引用、全部任务和全部模型用例身份。门禁不仅检查测试数量，还逐条要求每个模型用例存在且通过。未执行、跳过、异常不会视为完整。
- 清理：Docker --rm、请求级容器名称；独立缓存、临时二进制和驱动副本清理，原始报告和不可变证据保留。

Go 工具链原生行为参考：[go command](https://pkg.go.dev/cmd/go)、[模块下载与校验](https://go.dev/ref/mod#go-mod-download)；执行报告参考 [gotestsum](https://github.com/gotestyourself/gotestsum)。

## API 增量

- `POST /api/acceptance/plan`：兼容既有项目配置；未配置仓库返回 `intake-*`、技术栈/清单/入口/文档候选、缺口和快照。intake 不可直接执行。
- `POST /api/acceptance/automatic/design`：`{intake_id, documents: [相对文档路径], requirements_text?, scope?}`；调用真实模型，返回待确认方案、中文用例与原文、明确范围和 blockers。CLI 为 `auto-*`；Node/Python 模块沿用 `design-*`。
- `POST /api/acceptance/runs`：保留 `{plan_id,digest}`；auto 进入既有持久队列和统一详情页。未设计或不满足依据的 intake 返回 409。
- 既有记录、证据、导出和取消接口保留；不能通过直接创建执行器 profile 绕过方案确认。
