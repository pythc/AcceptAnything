日期：2026-10-18。状态：设计评审，未实施，未修改应用代码或被验收项目。

用户已认可参考组合：Linear 的整体视觉与列表、GitHub Actions 的流水线、Sentry 的缺陷层级、Allure 的步骤与附件。此次交付是同一套方案的三个页面，不是三选一。

## 统一结构

深灰中性色、低饱和紫色交互强调；固定全局侧栏；同位置的仓库目录、分支、提交、文件范围与环境；三个主体标签分别为验收流程、缺陷详情、证据溯源。正文以14–16px为实现基准，整行操作、键盘焦点、窄窗口布局在后续实现中验证。截图为生成式静态设计图，排版、文字和代码内容在实现前仍需按真实数据逐项核对。

## 验收流程

单行连接节点，窄窗口横向滚动，不折行；每阶段展示状态、耗时和所做事情。选中阶段展开具体检查，失败检查链接缺陷与原始输出。明确区分检查执行结束与验收通过。本次模型方案为复用，图中显示“已复用”，不将历史模型耗时作为本次执行耗时。运行态应采用同一节点结构，显示“正在执行”和实时耗时，不伪造已完成结果。

## 缺陷详情

左侧分组索引，右侧固定阅读结构：判定与P级、发生了什么、预期/实际/影响、源码位置、确认依据、复核记录。分类数量只出现一次。设计图中的分类数字作为分组快捷定位；若实现为筛选，列表必须只显示当前筛选类别，禁止同时保留其他类别。原始扫描报告不直接作为已确认缺陷。正常测试assert归入非缺陷，不计入待处理。

## 证据溯源

左侧按输入与执行步骤组织证据，右侧展示选定原件。关联链：源码版本 → 执行命令 → 报告 → 缺陷。原始诊断保留技术文本，解释、结论与操作文案使用中文。正文优先展示文件、命令、退出码和具体输出；完整摘要与校验信息折叠。构建失败展示编译诊断；浏览器步骤展示它实际产生的截图与轨迹，不能用无关图片充数。
