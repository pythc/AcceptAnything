# D027 · 发现降噪、去重与证据复核

日期：2026-10-18。用户要求不再把正常测试 assert 算成产品缺陷，区分待复核、工具误报与已确认缺陷，实现后完整复验。目标仍为 GMAH；不得为通过修改目标源码、测试或锁文件。

## 产品行为

“缺陷结论”改为“发现与复核”。默认列表只呈现待处理发现，分为“已确认缺陷”“待复核发现”“工具误报”“用例问题”，另有“全部”入口。原始数量、去重数量、合并重复数、各分类数量独立展示；“待处理”是已确认+待复核+用例问题的并集，不包含工具误报。目录和仓库页统一使用“待处理发现”，不把候选命中写成已确认缺陷。

原始报告、原始失败和历次执行保持不变。误报保留在单独分类，可打开原报告、复核原因、源码摘要和每次命中来源。历史运行可按当前策略只读复核，明确标明历史门禁不变；新运行冻结复核规则和证据，并用于本次 OPA 判定。

## 降噪规则

使用 Bandit 原始规则、Python AST、pytest 收集配置和 Hatch 打包边界共同验证 B101：

1. 命中必须来自 Bandit 的 B101，路径规范且位于冻结文件清单；文件内容 SHA-256 与本次源码一致。
2. 路径属于 pyproject.toml 明确的 pytest testpaths，文件符合 test_*.py 或 *_test.py，并被明确的 wheel 产品包范围排除。
3. 报告行号必须在实际 AST 中对应 Assert。
4. 缺少打包/收集依据、路径越界、生产源码、非 assert 行、文件缺失、内容变化或证据完整性失败，一律不豁免。

这类结论为“工具误报（产品缺陷语境不适用）”，不是说 Bandit 没有检测到 assert。原始检测是正确的，问题是将正常测试断言作为产品缺陷统计。未把 B101 全局关闭，也不把所有测试目录中的其他规则设为误报。

## 去重规则

仅合并工具、环境、规则、规范路径/行、组件、测试身份、实际声明和严重度均一致的观察。不同工具仅凭相同 CWE/标题、不同位置、不同版本、不同环境不自动合并。每组保留原始观察 ID、任务和所有原报告引用。

去重不删除报告或压低实际测试数量；失败测试断言仍参与门禁。当前 GMAH 原始600条没有满足条件的重复项，因此去重数为0。校准夹具证明：两份相同报告归为一组、保留两次来源；改变行号则保留两组。没有强行给本次数据制造“去重收益”。

## 验证与复核

扫描候选默认待复核，不因扫描器严重度或 HTTP 200 自动确认为漏洞。确认与豁免必须有对应报告及冻结源码证据。

本批 source-bound 复核目录 `standards/reviews/gmah-20261018.json` 绑定完整快照、观察身份、错误文本和所有相关文件摘要：

- 生产构建：原 npm run build 的 tsc -b 报 Logs.tsx:73 TS2322；核对源代码与 package.json，确认为生产构建缺陷。不是安全可利用性结论。
- 原回归失败：假客户端只预置5条回复，未满足现流程 final_answer 前的历史查询/更新等前提，responses.pop(0) 耗尽；与实现文件及原测试逐项核对，归为用例问题。继续阻断，不豁免失败测试。
- 其余扫描命中保持待复核，明确指出需要补充可达路径、输入来源、控制措施与实际影响。没有把58条未知全部自动确认或自动关闭。

参照 codex-security:triage-finding 的静态证据边界，仅复核已供给的报告，不开展无关漏洞发现，不修改 GMAH。GMAH 对应路径未发现适用 SECURITY.md，使用产品打包配置、源码和真实执行报告作为边界证据。工程实现与完整复跑属于用户明确要求，不将静态复核本身称为运行时安全验证。

## 人工证据复核入口

详情中的“记录证据复核”提交结论、验证方法/理由，必须引用该发现原报告。服务端采用追加日志、请求幂等、乐观版本校验、快照/指纹绑定；拒绝借用其他发现的报告或覆盖新版本。相同请求未知时不能换编号盲目重放。

人工记录不会改写旧门禁。下次计划生成时冻结适用复核；策略、人工复核或源码变化后须重新确认方案。失败测试只能作为已确认、待复核或用例问题处理，不允许以扫描误报方式直接豁免。该入口面向本机工作台操作者，不声称提供企业多用户身份签名。

## 判定与证据

新增“发现复核”阶段，随后执行质量门禁。每次归档 finding-review-policy.json 和 finding-review.json。证据核验检查原报告、逐条观察绑定、源码摘要、复核策略摘要和保存结果的一致性；失效时取消豁免/确认并保持待复核。

OPA 收到经过复核与确定性去重的派生任务，不修改 report 字段或原始任务。未知候选和用例失败仍阻断。真实 OPA 正反校准证明：仅正常测试 assert 可放行；换成生产 assert 则拒绝；原报告仍保留命中。

当前自动降噪只认证 Python pytest + 明确 Hatch wheel 范围的 B101。其他打包栈、复杂可达性、跨扫描器同源漏洞和风险接受仍保守留待复核；不以文件名、CWE、语言模型判断代替证据。原扫描报告可能为英文，分类与复核结论使用中文。
