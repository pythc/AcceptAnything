## 实现与复用

- 复用系统Git进行ls-remote、按SHA浅fetch、detached checkout；不重新实现Git协议。Pydantic约束输入，现有编译器生成测试，现有固定镜像、Huey、Playwright、pytest、k6及OPA执行判定。没有新增应用依赖。
- 新模块 acceptance/remote.py：地址规范化、引用校验、每次独立工作区、默认分支与分支清单、拉取/源码摘要、来源回执、冻结前漂移检查和归档一致性校验。
- acceptance/api.py 扩展统一入口，project_config.py / planning/service.py 传递来源与受审定的重定位绑定，provider.py 只允许精确快照/相同依据复用原草稿。unified.py 与集成目录按远程URL归组，分支和指定提交模式共用一个仓库身份。
- remote-source.json 原件保存远程地址、请求引用、实际提交、文件快照、拉取耗时、传输实现摘要；与冻结方案、执行上下文逐项校验，错误不会仅影响显示。页面、导出报告与下载均可追溯。
- 本地配置映射保持不变。新增仅服务端维护的 var/remote-project-configurations.json，GMAH绑定到既有外置配置及精确快照，不按仓库名称猜配方，不向被验收项目写配置。

## 输入与隔离边界

仅HTTPS、固定github.com/gitlab.com；拒绝URL凭据、查询/片段、端口、路径穿越、危险ref。不开启SSH、任意自建域名、file协议、重定向、Git钩子、继承的URL重写或凭据助手；不初始化子模块，不下载LFS，发现子模块/符号链接/LFS时阻断，不将缺失文件当完成。

单次Git命令90秒预算、输出2MiB、受控工作区256MiB检查；源码继续使用原5000文件/128MiB上限。失败拉取清理自己创建的目录；已确认来源保留用于溯源，当前没有自动历史保留期限/全局配额。

私有凭据机制读取服务端 ACCEPTANCE_GITHUB_TOKEN 或 ACCEPTANCE_GITLAB_TOKEN，通过临时askpass提供；不写进URL、参数、前端或报告。公开GitHub/GitLab已实测，私有账户权限场景未实测。macOS系统代理来自操作系统现有配置，修复Git不自动继承系统代理造成的超时；未更改系统代理设置。

不同源码版本不能静默复用GMAH既有配方：快照不一致时要求重新审定。通用远程仓库提供 acceptance.project.json 或外置项目配置后可进入既有生成/执行流程；缺独立标准、服务环境或负载/恢复配方时继续阻断。远程接入不等于任意项目零配置完整验收。

## API

POST /api/acceptance/remote/refs：{url} → 默认分支、分支列表、每项提交；超过1000项显示截取，可手填分支。

POST /api/acceptance/plan：本地{repository, configuration?}或远程{remote_url, ref_type:"branch"|"commit", ref, configuration?}，两者互斥。分支留空使用默认分支；提交必须完整40位SHA。

POST /api/acceptance/runs：{plan_id,digest}。冻结前重新验证本机checkout的HEAD/文件/状态及传输实现，不重新fetch。新执行后同原有 /api/runs/:id 查询和证据下载，历史读取不访问远端，也不依赖当前工作区状态。
