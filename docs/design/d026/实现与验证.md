## 504 的诊断与处理

原 5006 实例总预算 180 秒，早于调用方 210 秒；只加调用方超时不能解决。验收系统另建自己管理的本机 5007 实例，共享 5006 未改动。镜像版本、参数和请求汇总见附件 `gateway.json`、`gateway-request-summary.json`。

第一次把预算延长到 600 秒仍返回 504：初始 SSE 退出后，WebSocket 长时间无新数据，却耗尽总预算，没有机会进行 SSE 恢复和同轮快照读取。这不是持续有效推理的证据。

将 WebSocket 空闲限制为 15 秒，保留总预算 600 秒、会话超时 90 秒、客户端 630 秒，禁用重试和续写。随后大型完整方案请求在 92.655 秒返回 502 `upstream_no_final_response`：实际进行了 1 次 SSE 恢复、3 次快照读取，仍没有同轮最终正文。因此恢复预算分配得到修正，但**不能宣称网关已修好所有“无最终响应”问题**。远端生成是否已停止仍未知，不把本地请求结束当作远端停止。

本批业务通过改变验收系统的请求粒度打通：每批一个明确工作流，模型只输出用例输入、预期状态、中文标题/理由和原文依据；已经审阅的执行绑定负责 HTTP/页面步骤。去掉要求模型生成完整框架的大型嵌套 JSON，缩小失效面。不是用人工答案替代模型，也不是失败后悄悄切换型号。

## 验收系统自身修复

1. 新增服务决策表契约。模型预期必须用于实际断言，禁止写入请求、定位器或被响应捕获覆盖；输入按已审阅 JSON Schema 校验，不适用的用例直接拒绝，不反推答案。
2. 支持多个独立模型批次的不可变合并。严格核对依据、环境、原用例和顺序；不得修改或删除模型输入/预期；保存各批真实连接证据。
3. 队列恢复只处理真正开始执行的记录。修复启动时恢复扫描误杀刚入队记录的竞态；保留 `int-98df306de23e41a7` 原错误记录，没有把它归为 GMAH 缺陷。
4. 修复未采集耗时为 null 时的详情页异常，不补造时间。
5. 修复依赖与环境准备：固定依赖镜像；补齐镜像内平台原生依赖，目标锁文件不变；仓库回归复制到一次性可写容器工作区，避免测试写数据因只读挂载失败。
6. 浏览器交互绑定纠正：Ant Design 自动把双字按钮显示成“批 准／拒 绝”；旧提示 CSS 类名在当前版本不存在，实际提示具有 `role=alert`。改为归一空格的按钮文本匹配、可访问角色+原提示原文匹配。
7. 定位器修订创建派生草稿 `draft-c2aef374e9164908`，记录父草稿摘要、差异、原因、失败 trace；模型输入、预期状态、提示文本和原始模型响应保持不变。支持修改定位容器，但不允许更改可见文本断言内容。
8. 页面只读断言失败时仍采集后续业务状态；最终仍判失败。动作失败或 HTTP 前提失败则停止。真实浏览器正反校准验证“失败仍是失败”和“后续状态确实采集”。
9. 配方完整性进入 OPA；任一必验阶段、报告、清理、模型真实性或证据完整性缺失均不可放行。修复外置项目配置与旧配方目录混读的问题。
