# D041 运行中复核（持续追加）

所有 r1 检查均继续使用冻结摘要 95bc687d7e9949155ca04ac975d184b60ec52d9f72e62f190772f456a3e98832。以下是代码自审与当前模型原件观察，尚不代表对应目标项目缺陷。

## 已确认的执行协议问题

1. 服务发现顺序不能作为启动顺序。已改为拓扑启动，用中立夹具验证一个分支启动失败时另一个分支仍就绪；反向清理得到验证。
2. 单条 HTTP request 附带预期目前被拒绝，虽然可以改写为 poll，但这是不必要的协议限制。下一版复用同一可信断言器，支持请求的即时断言与可选结果捕获；请求纯采集时仍允许 expected=null，不忽略非空预期。
3. 模型把文档简写 `/add` / `/result` 当成示例实际地址，当前上下文没有提供 Blueprint 前缀。候选实现用 AST 提取路由及注册覆盖关系，保留来源与歧义。地址是接线信息，不由此生成正确性答案，也不静默替换已冻结模型输入。
4. 浏览器流程可能只在提交前检查表单可见，提交后只检查接口。下一版要求真实页面导航，并在最后一次 UI 写操作之后至少核对一个页面结果，避免把 API 通过冒充完整浏览器流程。
5. HAR 当前使用 attach，并已把全部响应 sidecar 文件纳入证据包；单独下载 HAR 不便直接读取正文。下一版采用 Playwright embed，保留自包含网络原件。
6. 服务节点运行记录应随节点状态持久化并在服务阶段展示；最终应将运行记录与 graph.json 绑定校验。当前整体任务有真实状态，分项节点仅在任务结束时进入持久记录。
7. Python 类方法的签名元数据缺少可变参数信息，模型据此错误地认为某些公开方法不能传路径。应只补齐真实 AST 签名；不按业务通过率变更被验收函数或传参。

- 冻结 Flask tutorial：独立 SQLite 数据库中的注册、登录、创建、修改、原生确认框删除链路通过。
