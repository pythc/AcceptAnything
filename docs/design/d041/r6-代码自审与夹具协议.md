# r6 通用夹具协议与代码自审

本轮继承 r4 的新模型原件，修复平台后重新执行，不重新向模型取答案，不修改原模型输入或预期。被验收仓库、原生测试和锁文件保持原提交。

## 通用环境准备

模型在声明式步骤中写入 `pyproject.toml` 时，平台按标准 `[build-system].requires` 和静态 `[project].dependencies` 识别构建夹具，缺省构建后端使用 pip 标准 setuptools 回退。按文档创建插件属于业务输入，不能让离线业务阶段自行访问外网。

新增可见的“用例环境准备”阶段：只在此阶段从官方 PyPI 下载二进制 wheel。原项目准备基线只读挂载，以已安装版本生成约束，拒绝同名夹具覆盖原发行包。保存依赖声明、约束、实际下载命令、完整 stdout/stderr、wheel 原件、大小和 SHA256。下载失败只影响使用该组夹具的用例。业务阶段使用内部网络及只读缓存，`PIP_NO_INDEX=1`，不修改仓库文件或默认依赖版本。

动态依赖、直接 URL、缺少静态发行包名及无二进制 wheel 的情况仍是明确缺口；未运行任意 setup.py 来猜测依赖，未将不支持情况转为通过。当前只实现 Python 标准夹具依赖，不泛称所有生态已支持。

每条业务用例从原生测试前的不可变基线复制独立文件系统、服务和网络。真实离线 editable 安装新增 `.pth` 后，当前场景解释器仅通过标准 `site.addpackage` 处理新增或变化的路径文件，并清空导入查找缓存。不重载被测模块，不修改业务对象；未声明构建夹具的用例不启用此适配。安装动作、插件结果和下一条用例未被污染分别验证。

## 冻结设计复验

原始记录先通过完整核验再进入计划，固定父 run.json 字节摘要。后续读取仍核对父记录、全部冻结源码与全部原始附件，拒绝任意字节漂移；不为读取同一份已核验输入而反复运行外部语法工具。老计划没有固定摘要时保留原校验路径。

语法分析最多进行三次本地无状态解析尝试，保存每次真实输出和耗时，并绑定原文、校验器、Babel 依赖摘要。它不是付费模型重试。历史拒绝和旧未知模型请求不改写。新编译可能让此前因工具超时而未执行的用例重新进入执行，但不能改变它的业务输入和预期。

## 复核关注点

- 调度顺序为准备/构建/原生测试/服务 → 模型原件复核 → 夹具依赖准备 → 分项业务执行 → 清理。夹具回执错误不全局阻塞，受影响用例仍需真实准备就绪才能执行。
- 缓存归属当前运行，业务挂载实际检查为只读；归档核验绑定模型声明、基线、镜像、退出状态、wheel 原件及每例挂载回执。
- 每个环境最终核对容器、卷、网络删除；清理失败仍保留异常。
- 原有“无关语法失败不阻塞业务”的回归需补上新增夹具前置任务的完成状态；没有删除该断言或放宽真实依赖检查。
- 全量检查和三个仓库复验以终态回执为准。用例定位器/SQL/排版断言问题继续保留，不能用实际输出改写预期获得通过。
