# r5 平台修复与复验边界

执行版本：517ba4201a643f4e24d710689b31b0066684f2740c0bbac076c13de0159a0665。本轮仅修复验收系统，未改被验收项目、原生测试、依赖声明或独立业务预期。

## 浏览器与诊断

head 中的标题不能用普通 DOM 文本匹配替代页面标题断言。复用 Playwright PageAssertions.toHaveTitle；contains 使用转义后的字面子串，保留等待机制，不把正则符号当模式。明确拒绝多元素定位器，不选择首个元素。单个 body 自定义标签 headtitle 不会误路由到页面标题，SVG title 歧义也会被拒绝。

HTTP 回执明确包装为 status/headers/value；实际使用不存在的包装根指针时标 case/error，既不重写原指针，也不修改预期。纯采集请求不因未使用的 pointer 元数据误报。正常业务预期不符仍 failed，传输/动作问题仍保留 error。

JUnit 只保存一份完整诊断正文，解决 message 与正文重复 JSON 及截断问题。超长 JSON 能完整回读，case 分类传递到任务报告与覆盖缺口。全部逐步原件保留。

## 语法复核证据

JS 回调校验使用成熟 Babel 语法分析，不执行文档脚本。新增冻结证据：引用输入摘要、校验器源码摘要、Babel 版本和入口摘要、执行参数、退出状态、实际 stdout/stderr 字节、耗时。归档按同一引用和同一冻结校验器绑定回执，再执行纯规则核对。缺失、重复、未使用的回执或引用/源码绑定不符都拒绝；保留 AST 约束，不能通过删改回调动作或预期通过复核。

旧记录缺少当时的语法工具原始 stderr/超时回执，不能追认具体错误类型。仅对明确记录“文档回调语法核对未完成；本条不执行”的旧保守拒绝复现原拒绝，绝不把它转为通过。旧记录已接受的用例继续核对；新编译使用新的工具回执。旧门禁和文件字节不变。

同一语法程序未改变时，新编译的引用绑定 AST 回执可以验证原已接受用例，避免归档再次启动可变进程。历史拒绝仍在核对原件时保留；新复验允许按当前可用工具重新编译原模型响应，原输入和预期不改写。
