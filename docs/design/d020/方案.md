# D020 · 从验收依据生成可执行用例

本批目标：把需求依据、测试设计、生成代码、真实执行和结论连接起来。扫描器继续作为通用质量检查；不能代替业务预期。

## 实施范围

- 输入本地仓库、独立需求/契约原文与结构化方案。可选模型把自然语言转换成同一结构；模型只输出草稿，不能写结论或执行任意代码。
- 每条标准必须引用输入原文，保留来源、摘要和引用位置。未映射标准阻止启动；明确排除的外部条件不生成用例。
- 用例模板支持数据表、矩阵与数值边界展开；覆盖正常、边界、异常、权限、状态、持久化等角度。未覆盖角度展示实际情况，不用固定百分比声称全覆盖。
- 生成新的 pytest / Playwright 测试文件，支持模块函数断言、API 多步流程、页面操作；OpenAPI 属性验证复用 Schemathesis。
- 目标代码仅在一次性 Docker 容器运行。测试驱动在目标容器之外，目标看不到预期断言、输出目录和宿主凭据。冻结的源文件、依据、方案、测试代码、执行器版本共同绑定本次执行。
- 使用现有 JUnit 归一化与 OPA 门禁；完整用例名单逐一核对，跳过、缺失、错误都不通过。步骤级实际值和原生报告保存为证据。
- 前端新增“设计验收用例”入口和“方案与用例”视图；原代码仓库、记录、缺陷、证据导航延续。

## 校验方式

先以独立契约对成熟本地项目生成此前不存在的测试，再真实运行。另用故意违反契约的隔离夹具验证失败能被检出；不修改被验收项目。检查缺来源、改代码/方案/执行器、漏跑、跳过、服务失败、取消与证据篡改等失效路径。

## 能力边界

没有模型连接时可以使用结构化方案和契约生成测试，但不能宣称已完成任意自然语言需求理解。模型草稿仍须核对业务含义，原文引用检查只能证明出处，不能证明语义正确。没有依赖/服务编排的复杂项目需要运行适配；本批不自动安装或运行仓库 shell 命令。仅给已列出的验收范围结论。
