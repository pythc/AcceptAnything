## 发现的问题

Flask Celery 示例的原始模型用例已正确提出通过 Flask 公开类创建应用，再调用子项目公开初始化函数。平台已把同版本地 Flask 包安装到该子组件，却在绑定时仅允许本组件的公开索引，误拒绝了这些父包调用。该问题属于通用的组件边界与安装证据不一致，不能归为被测项目缺陷，也无需修改业务输入或预期。

## 处理

1. 仅允许当前 Python 组件及其在同一环境按冻结源码路径安装的直接本地依赖。公开入口仍需出现在冻结索引中，同名歧义拒绝；未声明、第三方未索引或不确定的传递依赖不自动授权。
2. 模型原响应、逻辑输入、原文引用、业务输入及预期分别冻结。平台编译/观察修复后，可沿用原响应重新校验，然后创建新记录执行全部扫描、准备、构建、原生、业务与清理任务。
3. 原记录必须已结束且完整性有效，所有模型批次都明确完成；空设计、截断、未知终态、变化的源码或工具链拒绝复用。原模型仍为未决的需求不会凭空变成已有用例。
4. 新记录同时保留原草稿与新投影，原始输入/响应/回执逐字节复制。再次核对原投影和新投影，拒绝任何业务输入或预期篡改。设计来源标明原记录，不把复验时间当作新模型调用耗时。
5. 新建验收入口保留本地/远程，并提供显式“沿用冻结设计”选择。用户仍可选择重新识别和设计；被冻结来源不接受另一个仓库或分支配置。
