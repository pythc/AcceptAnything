# D040 分项复核与剩余边界

本文是实现代理根据冻结原文、实际输入和原始回执做的工程复核，不是用户审批。r4、r5 的原始模型判断、用例、失败与门禁均保留。下列复核意见不静默修改历史结果，也不把待复核项计为已确认产品缺陷。

## 先区分四件事

- 缺少依据：没有正确输出或适用条件。不能由实现或测得结果反推答案。
- 环境未就绪：已有契约，但所需服务、安装形态、数据或版本组合没有准备好。
- 平台能力不足：实际缺少接线、执行、比较或观察协议。模型说“不支持”不是充分证据，要对照协议和真实结果。
- 用例契约问题：引用失准、遗漏前提、替换了不等价入口、把示例排版当稳定输出，或没有验证声明的结果。这既不是扫描误报，也不自动证明目标项目有缺陷。

原生跳过、工具故障与断言失败是不同事实。正常测试函数中的 assert 经 AST 核对后保留为非产品缺陷；不删原报告。r4 的92条原始缺口包含重叠模型意见及汇总，不等于92个独立需求或缺陷，不能据此计算覆盖率。

## 边界

自动解决的是可确定的文档读取、包/环境接线、比较与证据采集问题；不能自动发明业务保证。仍缺通用多服务图、完整浏览器生成协议、安装/版本矩阵及架构证明范围。原始缺口清单与本复核意见并存，当前门禁保持未放行。后续若要关闭某条覆盖项，必须绑定具体源码、独立原文、适用输入和实际执行证据；同标题或模型一句“支持”都不够。
