# D022 · 统一完整验收流程

日期：2026-10-18。对象：110lab-assessment 本地仓库。历史记录保留，新增执行不覆盖旧报告。

## 问题

任意本地仓库入口原先只选择静态扫描和少量 Node/pytest 文件，未关联已接入的构建、数据库、Playwright、k6 与联合恢复配方。两种记录由不同详情页呈现；URL 同时残留 integration 与旧 run 参数。执行完成不能代表完整产品验收。

## 本批实现

- 统一新建入口：输入本地路径，识别已核验的完整项目配方和独立依据，展示全部阶段及排除范围，确认计划后启动。没有合格配方的仓库给出明确准备阻塞，不自动改成扫描模式。
- 阶段：需求与标准 → GPT-6 High 设计 → 新生成用例 → 仓库扫描 → 环境准备 → 用例核对 → 构建/回归 → API/数据库 → 浏览器/业务 → 性能/恢复 → 清理 → 归纳 → 门禁。
- 新编排复用既有成熟执行器：模型结构化提案、可信编译器、pytest/Node 驱动、Gitleaks、Bandit、Semgrep/njsscan、Syft、Trivy、Hadolint、Node/TypeScript、Python unittest、PostgreSQL、Playwright/axe、OWASP ZAP、k6、pg_dump/pg_restore 及文件摘要。
- 通用扫描及新生成测试保存为本次验收的子执行；父执行收据绑定子记录摘要，校验全部子证据与源文件摘要。
- 子执行从父任务冻结源码副本读取，不受模型等待期间原仓库变动影响。完整配方从本次源文件原件构建临时镜像，不安装到原仓库。项目配方仍有明确覆盖边界，不声称通用启动任意技术栈。
- 原始记录使用只读适配，全部进入同一个三 Tab 详情组件；保留仓库、快照、范围、环境、耗时、P 优先级、实际结论与原始证据。旧链接迁移成单个 run 参数。
- 完整性与门禁分开。必验阶段必须有真实终态；必验检查必须返回通过或失败；生成用例/扫描必须有可核验子收据。错误、跳过、缺失、模型未完成均阻止放行。子任务失败参与父 OPA 门禁。
- 完整流程未完成时状态为 incomplete，门禁 inconclusive。已执行但发现缺陷时才是完整执行后的 reject。扫描历史显示“所选范围检查 · 非完整验收”。

## 独立标准与生成

已审定项目配方包含 17 项检查，新生成方案从冻结的 CONTRACT.md 与 REGISTRATION-AND-TIMING.md 引用依据。结构化模板生成 39 项业务规则测试，来源明确标为结构化生成；模型新增草稿单独保存实际模型、High 强度、请求身份及引用校验。模型阻塞时仍运行模板及其他独立检查，但不替代模型阶段，也不把模型标为成功。

## 当前边界

完整环境配方目前适配已登记的 assessment 项目。未知仓库需要登记经过核验的启动、测试数据、负载与恢复配方；仅靠路径不能可靠推导这些信息。真实邮箱/外部身份等按既有排除范围保留。k6 仅本地 5 VU / 20 秒性能基线；联合恢复仅本地数据库、文件及替代实例业务读取，不代表生产 SLO 或跨地域灾备。摘要与容器隔离不等于独立可信执行签名。

## 修改历史

新增 acceptance/workflow.py 与 unified.py；API 增加完整计划/执行与统一记录/证据读取；Store/OPA 输入增加流程完整性及子任务结果；expanded 保留未完成状态；前端统一入口与详情，独立展示范围和完整性。

## 验证

详见同目录“实跑与验证.md”、自动化结果及 qa 截图。过程中发现的页面阶段合并异常单独修复并增加回归检查，未重启或覆盖正在执行的任务。

## 自审与修复

- 修复阶段默认状态与实际状态合并时的重复关键字错误，增加运行中投影回归。
- 强制模型设计成功时同时具有实际 GPT-6 Thinking / extended / stop 元数据和模型方案的子执行证据；只有模板不能满足模型阶段。
- 核对父子源码重叠清单、子记录摘要及原始报告；补跨任务证据访问、子记录篡改、源文件/配方变化等回归。
- 子任务门禁与父最终判定分别标识，避免三份gate-result都叫最终判定。
- 保留多份模型/结构化方案，避免后执行的模板覆盖模型方案的展示。
- 复合检查耗时使用实际检查区间；历史缺少区间时使用已验证报告的计时。不能把恢复末尾0.29秒的读取探针冒充整次恢复耗时。原始命令计时不改写。
- 窄窗口流水线换行，所有阶段可见；未知仓库不被静默降级成扫描。

- 主记录目录的检查、发现和证据数量与详情页一致；内部子任务不另列为“frozen-repository”仓库，避免形成重复验收对象。

用户在本线程明确同意“允许，停止旧实例后实测”。授权问题已说明停止旧5005共享实例会中断在途请求、旧结果仍为未知、使用修复版5006固定GPT-6 Thinking High且不切Pro。网关操作由原模型线程执行，具体镜像、208项回归、停止与新请求证据分别归档；本项目不伪造旧请求终态。

## 模型方案的受控生成

全量方案和单标准完整Specification两次真实High请求均达到180秒总截止；只确认无最终正文、请求作用域已清理，不猜测远端原因。保留这些失败执行。

新增模型决策表模式：每批只发送一条标准的原文片段（含原文件字符区间）、输入形状与输出类型。模型只设计输入和预期数据；Pydantic/JSON Schema核对变量与类型，再由已审核调用适配器及现有编译器生成pytest测试。适配器不读取实现作为答案，也不修正模型的错误预期。五条必验标准逐批核验；真实邮箱不生成模型批次。只有全部模型批次得到High完整响应，且每批生成用例实际执行并通过证据校验，模型阶段才能满足完整性门禁。

模型原始决策表、标准引用、投影版本model-decision-table-v1、生成方案及代码同时留证，不把固定框架结构描述为模型生成。网关504若没有精确终态，会继续阻止新请求，避免把HTTP错误当成任务已清理。
