## 原因

模型 HTTP 200、deepseek-flash、finish_reason stop，耗时44.4秒；原始响应和失败回执均保留。plugins/headroom-oauth2/SPEC.md 第43行描述覆盖 Authorization，下一行原文有两个空格缩进，模型引用省略了这两个空格。全文逐字子串判断因此拒绝，而非文字内容被改写。

## 修复

- 默认仍使用逐字原文匹配；仅逐字失败时，对连续Markdown正文行的0至3个ASCII空格缩进差异尝试唯一定位。不是编辑距离或语义近似匹配。
- 内部空格、词语、标点、Markdown符号、tab、4空格代码缩进、代码围栏或跨行反引号字面量差异均不接受；多个候选位置也拒绝。
- 使用定位到的准确原文作为编译依据，记录模型原引用、文档SHA256、字符范围、行号、定位方法；保留原始模型响应。业务步骤、输入和预期不做修订。
- 方案归档重新执行引用投影与定位证据检查；CLI原始输出重投影也经过同一规则。既有定位器修订仍走原有明确变更校验，不允许借引用处理改预期。
- 新请求在发送前归档准确prompt、system、模型配置（不含密钥和认证头）；拒绝方案也保留全部引用诊断，不只报第一条。有效方案在冻结执行时连同原始输入摘要与内容归档。
- 提示词要求source使用准确文档编号、quote为同一文档的连续原文并保留缩进；不自动重试、不替换模型或期望值。
- 前端可折叠查看仅缩进差异的定位记录；计划展示模型用例数，待确认项按纵向折叠列表呈现，避免长原因被flex挤成多列。新前端已构建；当前浏览器保留真实新方案状态，未刷新丢弃用户上下文。
