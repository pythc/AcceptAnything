# Lemma · 自主评审路径设计草案

2026-10-17 · 三张同一流程的状态图 · 待用户评审

这是设计提案，不是已运行的自主调度器，也不是对展示论文的真实评审结果。图片由内置 Image Gen 生成；论文排版、段落、页码和分支发现仅作界面示意，不能用于论文引用或数学判断。现有运行版本未因此修改。

## 用户目标

AI 读论文并根据核查所得决定下一步。流程图忠实展示已发生的执行路径、正在执行的动作和明确安排的任务；未来未决定的步骤不提前画出。节点表示具体动作，Agent 是执行者，同一个 Agent 可以反复出现，也可以整轮不调用某个 Agent。

## 三个时刻

1. 从阅读开始：左侧论文，右侧少量真实步骤。当前动作突出，末尾开放，写明下一步由结果决定。
2. 路径随发现生长：核查发现触发两条分支，引用分支的发现又追加补查。同一 Agent 再次被调用。选择节点后，在图下展开启动原因、原文定位、已有依据与任务记录。
3. 收束并交给读者：已执行分支合流、交叉复核和汇总。完成表示本轮核查结束，未解决的问题仍保留。点击“确定，查看结果”后才显示评审结论和 Agent 批注。

## 交互约束

- 阅读器和评审路径同时可见；第二张示意展开流程区域，方便查看分支与节点详情。
- 默认节点只有动作标题、执行者和状态。详细依据按需展开，不预先铺满所有 Agent 职责。
- 简明反馈说明当前动作、触发原因及已得到的产物；不展示模型私有思维过程。
- 状态用文字与形状共同区分；不用模糊的总百分比、预估全部步骤或虚构进度。
- 完成任务不等于数学命题得到证明；阅读全文也不等于全文已经核验。
- 点击节点定位原文属于查看任务上下文，不是提前公布最终 Agent 评审批注。
- 人工语义确认与“查看结果”是两个不同操作，不可混用。
- 三张图只是一个示例路径，不能将它反过来写成强制执行模板。

## 后续实现应补充的状态

本次出图集中展示用户指定的主流程，以下交互尚未画图：等待人工确认、工具失败后重试、证据不足时换方法、回退后产生新尝试、预算耗尽或用户暂停、恢复执行。应保留每次尝试及真实因果边，不覆盖失败记录。运行中单独的发现预览与最终结论需明确区分。

## 自审与边界

已逐图目视检查：三图沿用酒红色 Lemma 与论文阅读结构；第一张未预画全部分支，第二张包含真实因果式追加与节点详情，第三张具有汇流和结果确认。正文、节点与连线颜色清晰；栅格图未做浏览器计算对比度或响应式验收。第二张论文正文是生成排版，不应被当作原文。功能尚未实现，没有新增模型请求、改动服务或执行评审。
