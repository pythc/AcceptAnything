## 集成取舍与实际效果

| 能力 | 复用组件 | 本系统承担的工作 | 实测结果与边界 |
| --- | --- | --- | --- |

使用 CLI/API 集成，不复制商业产品代码。可复用执行能力与我们独有的需求依据、冻结、范围和证据核对分别维护。检查配方数量不因增加输出格式或页面入口而增加。

## 结构与可靠性约束

页面确认项目配置 → 冻结需求、标准、源码及工具 → Huey 持久队列 → 既有隔离执行器 → 原始报告 → 独立解析及 OPA → 三 Tab 详情与外部平台。

- API 与消费者是独立进程。队列持久化；同 run 重复投递只领取一次。HTTP 服务重启不把尚未执行任务当作失败。
- 已开始任务在消费者中断后不自动重放，尤其不能重发模型请求。未开始的任务可重新投递。
- 通用集成任务执行中支持协作取消；旧 native 完整配方只支持执行前取消，执行中的请求明确拒绝，避免假装已经停止。
- 浏览器和接口步骤共享 cookie；动态值保持原始类型。预期来自冻结独立文档，保留原文引用、实际响应、截图和 trace。只访问隔离目标。
- Dojo 重导入仅允许相同工具、规则、环境和文件范围的完整本地执行。范围漂移、未知严重性、不完整报告、导入来源均拒绝自动关闭旧发现；写入超时保留 unknown，不重试。
- GitHub 放行需要本地证据完整、冻结文件逐一与指定提交一致。PR 头部在发布前后核对；旧提交不代表新提交。`full` 默认要求完整验收，`scoped` 明确限定范围。外部导入报告不能冒充本平台执行。
- 内容哈希用于一致性检查，不等价于可信签名；当前本地操作者仍能同时修改文件和摘要，不宣称抵御管理员篡改。

## 使用方式

本地界面“验收仓库”可填写本地目录及可选外部配置文件路径。默认配置名 `acceptance.project.json`。外置配置可避免改动被验收项目。配置包括 schema_version、documents、specification、include_scanners、tasks、rules、exclusions；模型草稿可引用已经审阅的 draft_id。配置不接受宿主任意命令。

完整示例由 `scripts/verify_d025.py` 中的 configuration() 给出；该脚本创建隔离正负夹具，不用于替代真实产品验收。复现命令：

```sh
.venv/bin/python scripts/verify_d025.py
.venv/bin/python scripts/verify_d025_queue.py
.venv/bin/python scripts/verify_d025_ci.py
.venv/bin/python integrations/services/defectdojo/verify_lifecycle.py
```

复跑产生新记录，不能原地改写旧结果。DefectDojo 需对应本地服务可用；模型脚本另需服务响应，当前不自动重试未知请求。

完成记录的 CI 证明：

```sh
.venv/bin/python scripts/ci_gate.py RUN_ID --revision FULL_SHA --scope full --output var/receipt.json
.venv/bin/python -m acceptance.github_gate RUN_ID --repository OWNER/REPO --pr NUMBER --scope full --use-gh-auth --output var/github-receipt.json
```

第二条会写入已授权目标 PR；默认 full，不应为变绿改成 scoped。scoped 仅用于用户明确认可的限定范围。退出码 0=通过，1=拒绝，2=未知/不完整。发布命令使用本机 gh 授权或环境变量引用，不将密钥写入报告。未知写入须先查 GitHub 状态，不能盲目重复。

队列/API 操作使用 `scripts/local_service.py start|stop|status`；消费者单独用 `--worker`。API 的 start 会启动消费者，stop 只停止指定进程。缺陷同步使用 `scripts/integrations.py track CONFIG RUN_ID TASK_ID`，配置提供 url、token_env、engagement。
