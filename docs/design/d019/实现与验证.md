# D019 · 实时检查、本地仓库接入与用例登记

日期：2026-10-17。用户确认本批先支持任意本地路径，不接Git URL。

## 需求修订

1. 执行中展示当前检查/批次、正在执行状态、持续耗时与已返回结果；运行状态不冒充已验证结果。
2. 原“用例准备”改称“用例登记”，说明其输入和产物，保留真实耗时，不为显示耗时而人为延迟。
3. 新建验收可填写任意本地仓库目录，先确认检查计划和范围，再冻结执行。新仓库及记录进入原代码仓库/验收记录目录。

## 两个阶段实际做什么

基线校验核对冻结源文件、验收标准、编排/测试摘要，并准备隔离工作区及所需固定镜像；不在这一阶段判定业务通过。

用例登记读取已经存在的检查，核对标准编号与用例编号唯一、预期存在、执行器/层级有效，以及用例主题和步骤是否完整，然后保存case-registration.json。它是本地校验与写清单，不是调用模型设计新测试或执行测试，所以很快。此前run-5278b54f5b18只有登记计数，实际耗时6.2ms；本次修订后真实执行为15.05ms。旧记录没有产物时明确说明，不能回填假证据。

## 框架与接入设计

- acceptance/progress.py维护check_runs生命周期和current_activity；begin先保存，命令结束或异常后保存终态。结果仍只在收到报告后进入results，由已有验证器和OPA独立核对。刷新页面可以恢复当前检查和计时；未采集的旧记录不猜测正在执行哪条。
- expanded.py覆盖四层检查；projects.py覆盖已登记Node回归；engine.py覆盖内置样例。Playwright批量启动时将相关检查标为批次执行，单项结果等待原始报告。
- 用例登记清单保留基线摘要、目标摘要、标准、步骤和排除范围；按钮可直接打开该证据，页面说明登记不等于测试通过。
- 任意仓库接入复用IntegrationStore、Task/Profile、固定镜像、报告归一化和OPA，不另写扫描算法。新discovery.py只做文件/技术栈识别、计划与快照绑定。
- POST /api/integrations/local/plan接受repository、allow_registry、run_tests，返回可检查的计划；POST /api/integrations/local/runs只接受plan_id。参数不接受宿主命令或挂载配置。
- 预览绑定源文件列表、内容/模式摘要和固定工具链。启动前重新核对，冻结后再核对一次；变化后拒绝旧计划。重新识别按钮可生成新计划。
- 已识别工具包括Gitleaks、Bandit、Semgrep CE/njsscan、Syft CycloneDX、Trivy fs/config、Hadolint、ShellCheck；可选现有pytest和Node.js内置测试。报告与门禁复用既有适配器，软件物料要求至少1个可识别组件，测试要求至少1个且无失败，扫描命中需要复核。
- 公共漏洞库网络单独选择；项目源文件只读进入临时容器，不传入宿主凭据，不自动安装仓库依赖。缺少依赖时执行异常如实保留。
- 新目录、快照、范围、环境、任务、原件、发现和导出仍保留；主目录聚合local-配置产生的通用验收记录，打开时进入对应执行器与报告，不混用两个API的数据结构。

## 范围与限制

单次最多5000个文件、单文件8MiB、总计128MiB、100项任务。较大仓库可选子目录。排除依赖/构建产物/内部目录、符号链接、二进制、凭据和私密环境文件；不继承被验收仓库的扫描器控制配置，防止其替代本次标准。实际文件范围和排除数量随计划保存。

仅支持已接入工具识别的格式与规则。Python和JS/TS有当前专用静态规则，其他语言不声称已完成专用安全审计。业务流程、浏览器、性能、恢复需要独立标准、环境与测试数据；真实邮箱等外部服务无测试条件时不生成用例。仓库可接入不等于自动覆盖所有业务场景或所有语言。
